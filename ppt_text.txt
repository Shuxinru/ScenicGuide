需求场景与项目定位

=== 第4页 ===
需求分析
1. 人工导游成本高、旺季难预约，淡季服务缺位 
2. 扫码导览交互弱，千人一面，无法解答个性化问题 
3. 灵山景点分散，易错过九龙灌浴、梵宫演出等核心节点 
4. 游玩路线推荐无针对性，适配老人、亲子、摄影者等不同人群能力欠缺
游客端痛点
景区运营端痛点
景区运营端痛点
1. 导览内容更新繁琐，新增活动、景点无法快速同步
2. 咨询、游览、消费数据割裂，运营决策缺数据支撑
3. 缺少游客情绪感知渠道，服务问题难及时发现优化
4. 人工导览人力成本高，淡旺季人员调配难度大

=== 第5页 ===
项目定位
以无锡灵山胜境官方知识库为底座，打造集交互有温度、问答有准度、运营有数据于一体的 AI 数字人导览平台，覆盖游客全游览周期，低成本赋能景区智慧化运营升级。
核心定位
游客侧：打破传统导览的成本、时段与内容限制，提供千人千面的沉浸式个性化导览体验     景区侧：构建「游客交互 - 数据沉淀 - 运营优化」的完整闭环，实现导览内容高效迭代、服务质量精准提升
双端价值落点
平台集五大核心能力于一体：多模态交互、智能问答、个性化讲解、情感互动 以及后台分析。通过语音 + 文本双输入的多模态交互，搭配数字人实现自然沟通；依托专属知识库完成秒级精准问答，支持定制游览路线与景点深度讲解；可识别游客情绪，输出拟人化温情回应；后台则对全量交互数据可视化呈现，为景区运营决策提供有力支撑。

=== 第7页 ===
整体架构
         本项目采用分层解耦的前后端分离架构，自上而下分为四层，全链路支撑数字人导览与运营管理能力：
         前端层：游客端承载数字人、语音、对话交互；管理端提供仪表盘、知识库、系统配置能力
         后端服务层：基于 FastAPI 构建，以 REST API + WebSocket 为统一网关，核心包含 RAG 问答引擎、统计分析推荐业务模块
         外部能力层：对接 DeepSeek 大模型 API，提供对话生成与语义理解底层能力
         数据层：MySQL 存储业务数据，ChromaDB 承载向量检索，文件存储管理文档素材
系统整体架构

整体方案
 知识库管理：景区文档一键导入解析，自动切块向量化，导览内容高效迭代 
 数据仪表盘：咨询热点、客流倾向、情绪分布全维度可视化，支撑运营决策

   数字人交互：2D Q版数字人形象，口型表情实时驱动，语音 / 文本双渠道自然对话 
   智能问答：基于灵山官方知识库，覆盖景点、演出、交通、餐饮全场景精准解答 
   路线规划：按游玩时长、人群标签生成定制路线，配套伴随式景点深度讲解 
   情感互动：语义识别游客情绪，动态匹配数字人话术与表情 
   游览辅助：全程陪伴式导览体验，支持多轮对话上下文记忆
游客交互端
    双端数据互通，形成「游客交互→数据沉淀→运营优化→体验升级」的完整业务闭环

核心技术及实现方案

=== 第10页 ===
核心技术一
RAG检索增强问答
技术定位：针对灵山景区场景定制的全链路可控问答方案，从检索到生成全环节管控，保障回答精准可溯源。
1.问题预处理：ieba中文分词提取核心关键词，自动过滤无意义疑问词，精准锁定游客真实诉求。
2.三路异步并行检索：基于 asyncio.gather() 实现毫秒级并发：
   向量语义检索（ChromaDB）：捕捉语义相似度，覆盖泛化问题
   关键词召回：匹配高频问答对，命中固定场景问题
   结构化字段查询：对接 8 张景区业务表（景点 / 票务 / 演出 / 路线等），兜底事实数据
3.可控式 LLM 生成：多源检索结果注入系统提示词，叠加数字人人设、游客偏好；配套8条防幻觉规范，严格限定仅基于灵山官方资料作答。
4.输出后处理：自动清洗Markdown格式标记，输出纯净文本，原生适配语音播报与移动端展示。
核心优势：从根源压缩大模型幻觉空间，所有事实结论均可溯源至灵山官方知识库，回答准确、合规、可靠。

=== 第12页 ===
核心技术二
知识库构建流程
灵山专属知识库构建流程（如右图）：
1.文档解析：兼容 PDF、DOCX、TXT、MD 全格式，自适应编码识别，统一提取纯净文本。 
2.中文分块：递归字符分割，500字/块、50字重叠，按中文标点断句，保障语义完整。 
3.本地化向量化：Sentence Transformer 本地推理，多语言模型批量编码，零 API 成本、数据更安全。 
4.双库协同入库：ChromaDB 存向量用于语义检索，MySQL 存原文用于后台管理，双库数据一一映射。 5.问答对精准兜底：支持管理员录入高频问答，配置关键词标签，固定问题直接精准命中。
